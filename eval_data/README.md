# Eval input fixtures

Input datasets consumed by the evaluation harnesses in `scripts/`. See
`docs/evaluation.md` for the full evaluation workflow — this file only
covers what lives here and where each one comes from.

| File | Consumed by | Source |
|---|---|---|
| `reference_topics.json` | `scripts/eval_retrieval.py` | Converted from `reference_topics.xlsx` via `scripts/convert_reference_sheet.py`. 17 topics, hand-curated, each with a human-confirmed set of expected relevant papers. |
| `reference_topics.xlsx` | (source only — not read directly by any script) | The raw, human-maintained spreadsheet. Binary and not diff-friendly, so it's `.gitignore`d — `reference_topics.json` (its reviewable, converted output) is the tracked source of truth. Re-run `scripts/convert_reference_sheet.py` whenever the spreadsheet is updated. |
| `stage1_ragas_questions.json` | `scripts/ragas_eval.py` | Hand-curated, 24 scenarios across single-paper, cross-paper-comparison, multi-turn, and deliberately-unanswerable categories. Not generated from anything — edited directly. Each scenario's own `_meta` block records how it was independently verified against the real pipeline. |
| `chat_web_relevance_redteam.jsonl` | `research_agent/evals/runners/run_chat_relevance.py` (`uv run python -m research_agent.evals.cli run --suite chat_relevance`) | Hand-curated, 11 cases covering the R7A-R7E.5b chat/web relevance red-team scenarios (topic drift, query-only/topic-only mismatches, temporal traps, stale pool reuse, empty pool, fail-open/fail-closed embedding failure, high-similarity direct-relevance bypass, prompt injection, judge uncertainty). Mock (default) or live (`--mode live`, R7D.2/R7E.5) — 3 cases are `mock_only: true` (each with its own `mock_only_reason`) and are skipped, not forced, in live mode. See `docs/evaluation.md`'s "R7E — chat relevance evaluation arc" section. |
| `report_quality/` | `research_agent/evals/runners/run_report_quality.py` (`uv run python -m research_agent.evals.cli run --suite report_quality`) | `manifest.jsonl` + `fixtures/*.json`: 8 hand-curated, fully synthetic report-quality fixtures (3 "good" baselines across the foundational/analytical/expert templates sharing identical evidence, plus 5 adversarial/flawed cases covering citation misattribution, low-synthesis verbosity, source-side prompt injection, report-prose evaluator injection, and stacked structural corruption). Deterministic/mock mode (R6B, the default) — 6 frozen hard-failure identifiers, no OpenAI calls. `--mode live` (R6C, complete and frozen as of tag `r6c-report-quality-evaluation`) adds two opt-in live judges — real, billable model calls. See `eval_data/report_quality/README.md` and `specs/report-quality-evaluation-plan.md` for the frozen rubric/schema and aggregation policy. |
| `report_refinement/` | Not yet registered in any CLI suite — schema/loader only (`research_agent.evals.report_refinement_inputs.load_report_refinement_examples`) | `manifest.jsonl` + `fixtures/*.json`: 7 hand-curated, fully synthetic **pair** fixtures (an unrefined draft + a bounded refined report, same topic/template/evidence) for R6D, the future paired refinement-effectiveness benchmark — covering a clear grounding improvement, a holistic synthesis improvement, a justified no-revision tie, a cosmetic-rewrite tie, a citation regression, a mixed improvement/regression tradeoff, and a structural regression. **R6D.1 (this dataset) is schema/fixtures/loader only** — no live judges, no CLI registration, no pairwise aggregation, no claim that refinement helps has been measured yet. See `eval_data/report_refinement/README.md` and `specs/report-quality-evaluation-plan.md` section 8 for the frozen pair schema. |

Nothing in this directory is modified by running an eval — these are
inputs only. Eval *outputs* live in `eval_results/` (see
`docs/evaluation.md`'s artifact policy).
